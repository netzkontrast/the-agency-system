# Overnight brief template (for epic, long-running pieces)

The most viral Opus 5.5 music video came from one long, rich, voice-dictated brief (see overnight-run.md). This is that brief's structure, generalized. Fill the [brackets] with the user, confirm budget and checkpoints, then hand it to the long-running agent (or run the studio process with it as the director's input).

---

**The target.** I've included [the song / source video / link]. It's about [what it means]. Do a complete end-to-end pass making [a new music video / film] for it. Use the exact same audio. Think and feel deeply about how to visually represent every lyric; you don't need to anchor to the current style, and you may do anything, including abstract motion graphics.

**Look and freedom.** I want beautifully rendered JavaScript animation with [texture: papery / watercolor / risograph / ...], pushed in whatever direction you think is best and aware of the current zeitgeist. Be mindful of aesthetics: no generic AI slop, no default Pixar look. Find a coherent style that also works well with the image and video models available. [Visual anchor, e.g. K-pop direction, used loosely.]

**Materials and tools.** You can use: [folders of past work, reference compendium, skills], [image model + key: character sheets, style sheet, sets], [video model + docs: reference motion, lip-sync], [sound design API], web search for references in motion design and JavaScript animation. Think about what is realistic for your capabilities.

**Characters and world.** Design a protagonist [who represents X / based on Y], then backup dancers and supporting characters as needed, and the sets. Generate a style sheet first and keep everything consistent with it.

**Base footage (optional, the rotoscope method).** Generate scenes with the video model using the character and set images, passing cut-up sections of the song as audio reference so the timing and lip-sync are exact. Build verification loops to confirm sync, and regenerate as needed. Not every shot needs singing: use inserts, other actions, shots without characters, like a real music video. Then reconstruct everything from scratch in JavaScript over the base footage, so the viewer only sees your drawing, with the base giving you real motion, physics and continuity.

**Meaning and culture.** Audit the references and memes the audience will recognize [list the zeitgeist: events, memes, in-jokes]. Integrate them where they serve the lyric; straight inserts in an internet-brutalism style are allowed. Anchor to visual references people will understand. Audience: [who, where it posts].

**Attention.** A strong visual hook in the first seconds. Lyrics as motion graphics embedded in the shots: plan composition so backgrounds are calm where lyrics are big (e.g. characters right, lyrics left). Vary it: sometimes subtitle-like, sometimes huge. At the hook, lyrics are big and present. Study how great music videos (K-pop especially) direct attention with visual patterns.

**Rigor.** Plan composition and timing before building, because things that weren't thought through clash when combined. Revisit and iterate: watch the whole video several times, screenshot individual parts, and ask whether each is at the bar. Nail the animation style. [Reference repo/video] is a good foundation but not the bar; aim much higher.

**Budget.** [Usage plan; credits cap, e.g. ~$X of image/video credits]. Spend economically but fully; monitor usage.

**Bar.** Make it a banger for [platform]; the stretch goal is better than anything seen before. Make no mistakes.

---

Before launching: agree the budget, the tools the user actually has (offer free routes, see toolbox.md), and whether there's a storyboard checkpoint or it runs truly unattended. For code-only styles, drop the base-footage section.
