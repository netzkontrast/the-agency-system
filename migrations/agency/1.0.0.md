# Agency System State Migration Runbook (v1.0.0)

> **Spec Ref**: Plan/019-state-migration-from-bitwize

This document serves as the migration runbook for existing `bitwize-music` users upgrading to the unified `agency-system`.

## Inferred bitwize-music v0.91.0 state shape

The migration infers the following standard `bitwize-music` JSON schema shape based on the `cache/state.json` file format. It assumes that top-level metadata tracks genres containing dictionary objects mapped by album slugs.

```json
{
  "version": "1.2.0",
  "generated_at": "...",
  "config": {
    "content_root": "...",
    "artist_name": "..."
  },
  "albums": {
    "GenreName": {
      "album-slug": {
        "slug": "album-slug",
        "title": "Album Title",
        "genre": "GenreName",
        "tracks": {
          "track-slug": {
             "slug": "track-slug",
             "title": "...",
             "status": "..."
          }
        }
      }
    }
  },
  "ideas": {},
  "skills": {},
  "session": {}
}
```

## Pre-flight

Before executing the migration, ensure your legacy data exists in its standard location. Specifically, check that `~/.bitwize-music` exists, that you are running Python ≥ 3.11, and that you have write access to `~/.agency-system/`.

```bash
# Verify legacy state cache and configuration exist
ls ~/.bitwize-music/cache/state.json
ls ~/.bitwize-music/config.yaml
```

The migrator relies on these files. If they are missing, the migrator returns `{"reason": "no bitwize state found"}` and exits without modifications.

## Dry run

You can execute a dry-run migration to understand what transformations will be made before writing to the new `~/.agency-system` location.

```bash
python state/migrators/bitwize_v091_to_agency.py --dry-run
```

Expected Output:
`{"would_migrate": <int>, "would_skip": 0, "input_hash": "<sha256_hash>"}`

## Real run

Execute the migrator directly to commit the changes safely onto your filesystem.

```bash
python state/migrators/bitwize_v091_to_agency.py
```

Expected Output:
`{"artefacts_written": 2, "input_hash": "<sha256_hash>"}`

## What gets written

1. `~/.agency-system/cache/state.json`: A namespaced state.json containing your `bitwize-music` data safely inside a `music` node.
2. `~/.agency-system/config.yaml`: The unified configuration settings merging the original defaults with your overrides.
3. `~/.agency-system/backup/<UTC-ISO>/{bitwize-state.json,bitwize-config.yaml}`: A safety snapshot of the source bitwize files before renaming.
4. `~/.bitwize-music/DEPRECATED.md`: A deprecation flag written into the old environment to notify standard tools of your move.

## Backup and rollback

The migrator automatically performs backups of the source paths `~/.bitwize-music/cache/state.json` and `~/.bitwize-music/config.yaml` to the destination's backup directory prior to modifying state.

If something breaks, look in:
`~/.agency-system/backup/<UTC-ISO-timestamp>/`

To rollback your state manually:
```bash
cp ~/.agency-system/backup/<timestamp>/bitwize-state.json ~/.bitwize-music/cache/state.json
cp ~/.agency-system/backup/<timestamp>/bitwize-config.yaml ~/.bitwize-music/config.yaml
rm ~/.bitwize-music/DEPRECATED.md
```

## Idempotency

The migrator caches a stable hash of your `~/.bitwize-music/` sources as `_migration.input_hash` upon successful migrations. Subsequent runs safely terminate and return `{"reason": "already migrated", "input_hash": "..."}`. Re-runs are no-ops.

## Troubleshooting

- **Schema Errors:** `{"error": "schema", "msg": "..."}` — The legacy state must contain a valid JSON object structure. Check `~/.bitwize-music/cache/state.json` manually if you run into this error.
- **Write Errors / Disk Full / Lock Contention:** `{"error": "write", "msg": "..."}` — Validates disk capacities, path accessibility, and standard locks. Your previous environment remains completely untouched via POSIX standard atomic rename constraints (`os.replace`).
